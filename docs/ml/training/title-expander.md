# Training: ML-001 Title Expander (v2.0.0)

- **Notebook:** `notebooks/01_train_title_expander.ipynb`, generated by `scripts/generate_kaggle_notebooks.py` (edit the generator, not the notebook).
- **Spec:** `docs/ml/models/title-expander.md`
- **Status:** authored 2026-11-26; not yet run.

## Data
- **Source:** O*NET 31.0 text database (CC BY 4.0). The notebook downloads it and verifies SHA-256 `6883548a…23a9`, or uses a copy attached at `/kaggle/input/onet-db`.
- **Files used:**
  - `Occupation Data.txt`;
  - `Sample of Reported Titles.txt` (curated, common titles);
  - `Job Titles.txt` (formerly `Alternate Titles.txt`);
  - `Software Skills.txt` (formerly `Technology Skills.txt`).

  Older file names are also accepted.
- **No real user data.**
- **Examples:** one per (anchor title, level).
  - Input: `expand titles: <anchor> | skills: <1-5 O*NET software skills, or 'general'> | level: <ANY|ENTRY|MID|SENIOR|LEAD>`. This is exactly the format the Findrr runner sends.
  - Target: up to 5 other titles of the same occupation, comma-separated and sorted.
  - For ENTRY, SENIOR and LEAD, targets come from that occupation's titles containing level words (for example "Senior"), when at least 3 exist. Otherwise neutral titles are used.
  - Titles containing commas are excluded, because the comma is the output separator.
- **Split (D-009):** by input title. Each normalised anchor title is hashed (seeded) into train, val or test (80/10/10), so the same input wording never appears in two splits, in any occupation. Each occupation keeps at least one training anchor, so every occupation's titles are learnable, as in the app, where the dictionary is fixed and only the user's wording is new. Test anchors may still appear as training *targets*.
- **Measured locally on 2026-11-26 (data preparation only):** 26,549 examples from 894 occupations. Train: 21,304 (894 occupations, 3,797 anchors). Val: 2,720 (432 occupations, 483 anchors). Test: 2,525 (403 occupations, 459 anchors). No anchor is shared between splits. 22 test anchors (110 examples) never appear in training at all, as input or target.
- **Extra training inputs (D-010):** up to 30 O*NET job titles per occupation become additional level-ANY training inputs, with that occupation's neutral titles as targets. They exclude existing anchors, titles with level words, and any wording used as a val or test anchor in any occupation. Measured locally on 2026-11-27: train grows to **42,624 examples and 22,967 distinct input titles** (from 3,797); val and test are unchanged, with no anchor overlap.

## Training
- **Model:** `google/flan-t5-small`, full fine-tune.
- **Settings:** AdamW, learning rate 3e-4, cosine schedule with 10% warmup, 15 epochs (D-010; was 5), batch size 32. The best checkpoint is chosen by validation loss.
- **FP32, not FP16:** T5 checkpoints overflow in FP16, and the T4 has no bf16 (deviation from the spec; see the spec's implementation notes).

## Evaluation (amended by D-007 and D-009)
Evaluation runs on held-out input titles, using the runner's **constrained** decoding: `num_beams=2`, `do_sample=False`, `repetition_penalty=1.0` (off, D-010), `max_new_tokens=64`, with a trie over the 45,712 comma-free O*NET titles. Titles that can't be followed cleanly by the separator token are skipped. That is 409 titles: 407 contain commas, and 2 have a last token that merges with ",".

| Metric | Criterion |
|---|---|
| Occupation precision (generated titles in the input occupation or a Primary-Short related one) | >= 0.75 (approved, PR #27) |
| Valid title ratio (raw output; a cut-off title counts as invalid) | >= 0.85 |
| Repetition rate (raw output) | < 0.05 |
| AC-ML-001.1: distinct titles for "Software Developer" | >= 3 |
| ROUGE-L, BLEU-4, mean distinct titles, occupation precision on never-seen wording (D-009) and on 500 seeded training inputs (D-010) | reported only |

Reference points for occupation precision on this test split (D-009), drawing 5 random titles from those used as training targets:

| Baseline | Score |
|---|---|
| Random dictionary title | 0.007 |
| Same SOC major group (e.g. 15) | 0.114 |
| Same SOC broad group (e.g. 15-125x) | 0.732 |
| Same detailed SOC code (e.g. 15-1252.xx) | 0.929 |
| Gold references | 1.0 |

Under the earlier occupation-disjoint split, the broad-group baseline restricted to learnable titles was 0.579, not the 0.736 used to set the threshold (D-009).

The notebook prints 15 sample predictions with the metrics. If any criterion fails, it does **not export**.

**Bundle:** it also ships `titles.json` (the constrained vocabulary). The app requires it and builds the same trie at load (about 2 s).

**Verified locally on 2026-11-26 (no training):** the export code, run on the untrained base model, produced a bundle. The app registry accepted it, and `TitleExpanderRunner` returned only dictionary titles.

## ONNX export (D-004, v2.1.0)
- After training, `export_t5_bundle` (embedded from `src/findrr/ml/t5_onnx_export.py`) writes `encoder.onnx`, a KV-cached one-step `decoder.onnx` and `embeddings.npy`. It stops if the ONNX logits differ from the model's own logits by more than 1e-3.
- **All metrics are measured on the exported files**, using the app's decoding code (`src/findrr/ml/t5_onnx_decoding.py`, embedded verbatim). This evaluation runs on the CPU (about 20–30 minutes for about 3,000 requests).
- **No retraining for an accepted v2.0.0 model:**
  1. Upload your extracted `models/title-expander/v2.0.0/` folder as a private Kaggle dataset.
  2. Attach it to the notebook.
  3. Set `REUSE_BUNDLE_DIR` in the training cell to its path under `/kaggle/input/`.

  The notebook checks the bundle's checksums, ID, version and acceptance, then skips training. The manifest records `reused_bundle`.
- **Verified locally on 2026-11-27 (no training):**
  - the notebook ran end to end in reuse mode on the installed v2.0.0 bundle (evaluation cut to 40 inputs, export gate opened for the dry run only);
  - ONNX parity was 3.8e-5;
  - the app runner, run separately on the installed v2.0.0 weights exported the same way, returned the same titles as PyTorch on 200/200 test inputs.

## Transfer
1. Download `title_expander_bundle.tar.gz` from `/kaggle/working`.
2. Run `mkdir -p models/title-expander/v2.1.0 && tar -xzf title_expander_bundle.tar.gz -C models/title-expander/v2.1.0`.
3. Run `findrr model inspect ML-001`, which must report `Integrity Verified: Yes`.
4. Keep the notebook output (metrics and manifest) as evidence for `docs/ml/evaluation-reports/`.
