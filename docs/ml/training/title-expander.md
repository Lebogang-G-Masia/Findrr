# Training: ML-001 Title Expander (v2.0.0)

- **Notebook:** `notebooks/01_train_title_expander.ipynb`, generated by `scripts/generate_kaggle_notebooks.py` (edit the generator, not the notebook).
- **Spec:** `docs/ml/models/title-expander.md`
- **Status:** authored 2026-11-26; not yet run.

## Data
- **Source:** O*NET 31.0 text database (CC BY 4.0). The notebook downloads it and verifies SHA-256 `6883548a…23a9`, or uses a copy attached at `/kaggle/input/onet-db`.
- **Files used:**
  - `Occupation Data.txt`;
  - `Sample of Reported Titles.txt` (curated, common titles);
  - `Job Titles.txt` (formerly `Alternate Titles.txt`);
  - `Software Skills.txt` (formerly `Technology Skills.txt`).

  Older file names are also accepted.
- **No real user data.**
- **Examples:** one per (anchor title, level).
  - Input: `expand titles: <anchor> | skills: <1-5 O*NET software skills, or 'general'> | level: <ANY|ENTRY|MID|SENIOR|LEAD>`. This is exactly the format the Findrr runner sends.
  - Target: up to 5 other titles of the same occupation, comma-separated and sorted.
  - For ENTRY, SENIOR and LEAD, targets come from that occupation's titles containing level words (for example "Senior"), when at least 3 exist. Otherwise neutral titles are used.
  - Titles containing commas are excluded, because the comma is the output separator.
- **Split:** whole occupations are assigned to train, val or test (80/10/10), stratified by SOC major group. No title is shared across splits.
- **Measured locally on 2026-11-26 (data preparation only):** 26,549 examples from 894 occupations. Train: 21,289 (717 occupations). Val: 2,675 (90). Test: 2,585 (87).

## Training
- **Model:** `google/flan-t5-small`, full fine-tune.
- **Settings:** AdamW, learning rate 3e-4, cosine schedule with 10% warmup, 5 epochs, batch size 32. The best checkpoint is chosen by validation loss.
- **FP32, not FP16:** T5 checkpoints overflow in FP16, and the T4 has no bf16 (deviation from the spec; see the spec's implementation notes).

## Evaluation
Evaluation runs on held-out occupations, with the runner's decoding settings (`num_beams=2`, `do_sample=False`, `repetition_penalty=1.2`, `max_new_tokens=48`).

| Metric | Criterion (spec) |
|---|---|
| ROUGE-L | >= 0.75 |
| Valid domain title ratio (generated titles found in the 46k-title O*NET dictionary) | >= 0.85 |
| Repetition rate (duplicate titles within an output) | < 0.05 |
| AC-ML-001.1: distinct titles for "Software Developer" | >= 3 |
| BLEU-4 | reported only |

If any criterion fails, the notebook **does not export**. `ALLOW_EXPORT_BELOW_ACCEPTANCE = True` exports anyway, but records `acceptance.passed = false`, and the app then refuses to load the model.

## Transfer
1. Download `title_expander_bundle.tar.gz` from `/kaggle/working`.
2. Run `mkdir -p models/title-expander/v2.0.0 && tar -xzf title_expander_bundle.tar.gz -C models/title-expander/v2.0.0`.
3. Run `findrr model inspect ML-001`, which must report `Integrity Verified: Yes`.
4. Keep the notebook output (metrics and manifest) as evidence for `docs/ml/evaluation-reports/`.
